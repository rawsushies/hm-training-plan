# WeRunIt v4: architecture and status

v4 is an evolution of the v3 app, not a rewrite. Unchanged: framework-free classic scripts, Google sign-in, Firebase UID as
identity, offline-first account-scoped storage, record-level sync with rev concurrency, migration, live updates, app ID
`com.hmtrainingplan.app`, Firebase project `we-run-it`, release keystore.

## Modules (all in `public/js/`, loaded in this order after the main script)

| File | Role |
|---|---|
| `brand.js`, `motion.js`, `css/werunit.css` | Logo, tokens, motion. `GlassPill` = frosted spring pill (leading `springF(19,0.55)`, trailing `springF(11,0.72)`, stretch, `blur = 1.5+6.5·sn`, frost `rgba(225,225,245,0.14·sn)`), reference demo (470×222, 12 s loop, SEL [3,1,2,0]) in *Tentang*. |
| `schedule.js`, `race.js`, `views-v4.js` | Flexible schedule, race events + replanning, race workspace (pace, splits, hydration, fuel, HR, checklist, sheet). |
| `ui-glass.js` | `segPill()` and automatic upgrade of every single-select `.seg` to the same glass pill. It moves only when the selection changes; reduced motion → no animation. |
| `social.js`, `views-social.js` | Friends (see FRIENDS.md). |
| `notify.js`, `views-notify.js` | Android notifications (see NOTIFICATIONS.md). |
| `weather.js`, `views-weather.js` | Open-Meteo weather + tips (see WEATHER.md). |
| `shoes.js`, `integrations.js`, `views-m4.js` | Shoes + integrations (see INTEGRATIONS.md). |

Server scaffold (not deployed): `functions/` (Strava).

## Data model additions (users/{uid}/…)

Single records `plan/schedule`, `plan/profile`, `plan/race`, `plan/planmap`. Map records `plan/event_*`, `plan/share_*`.
Optional shoe fields. Top-level `invites`, `requests`, `friendships`, `shares`, `goals/{id}/contrib`,
`users/{uid}/blocks`, `users/{uid}/inbox` (server-written), `serverOnly/**` (no client access).
New fields are written only when set, so a v3 user's records do not change on upgrade (tested).

## Native level

The APK user agent reports `HMTPNative/2` (adds local notifications + Health Connect; minSdk 26). `version.json` keeps
`minNative: 1`, so older APKs keep receiving web updates; the features that need the new binary say "Perlu update aplikasi".
