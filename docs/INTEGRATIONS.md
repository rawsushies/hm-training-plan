## Shoes

- Optional fields `brand`, `model`, `use` (daily/tempo/long/race/trail), `initialKm` (km before using the app), `since`.
  v3 shoe records stay byte-identical (no sync churn).
- Mileage = `initialKm` + km from real (non-sample) runs; the card shows both parts.
- Rotation: a suggestion for the next session from use fit + wear, with the reason. Race shoes are only suggested for fast sessions and the race. There's also a 28-day share per shoe.
- Catalogue (`public/js/shoe-catalog.js`): 16 current models with brand, model name and release date, each linked to the public source it came from and the retrieval date ("sekitar" = first retail listing, not an official launch). Below the facts, a Plus/Minus tab holds WeRunIt's own short notes, labelled as opinion. No prices or lab specs. One tap adds a model to "Sepatuku".

## Automatic shoe catalogue (weekly)

- `.github/workflows/shoes.yml` runs every Monday 02:17 UTC, by hand, and whenever `scripts/shoes/**` changes. It reads the
  public `/products.json` feeds of running retailers (Pace Athletic, Up There Athletics, Vancouver Running Co.). There is no
  login and no private API, `robots.txt` is honoured, the bot identifies itself, and it waits between requests.
- `scripts/shoes/lib.mjs` keeps only whitelisted running brands and running shoes. It normalizes model names (no gender, width,
  colourway, edition or collab), takes the **first-listed date** at the shops (shown as "Pertama terdaftar di toko"), takes the
  product image with a credit and link to the shop page, and parses specs **only when the shop text states them** (weight, drop,
  stack, plate, stability tag, waterproof, price).
- **Plus/Minus are generated by rules** from those specs. Each line cites the number or flag it comes from (for example
  "Ringan untuk kategorinya (245 g vs median 262 g)"). With no data there is no note, and nothing is invented. No AI is used.
- Output is validated (https only, dates not in the future, known brands) and committed to the **`data-shoes`** branch only when
  it changed. The app fetches `raw.githubusercontent.com/…/data-shoes/shoes.json` (cached 12 h, sanitized again in the app,
  offline-safe) and merges it with the hand-written seed (`public/js/shoe-catalog.js`). Seed facts and notes win; the auto data adds
  photos, specs and new models. No app release or deploy is needed for catalogue updates.
- Photos belong to the brands/shops and are shown with credit (owner's decision; not licensed).
- The weekly schedule only starts after the workflow file is on the default branch (`main`). Until then it runs on pushes to this branch.
