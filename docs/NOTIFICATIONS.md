# Notifications (v4)

## What works where

| Platform | Behaviour |
|---|---|
| Web / PWA | Preferences + a 7-day preview only. Never calls `Notification.requestPermission()`, never schedules anything (e2e-tested). A browser tab cannot deliver background reminders reliably, and no `setTimeout` loop is used to fake it. |
| Android APK **with** `@capacitor/local-notifications` (8.3.1, first in the APK built from v3.10.0) | Real reminders, handed to the Android alarm manager. They fire with the app closed and are restored after a reboot (`BOOT_COMPLETED` receiver from the plugin). |
| Older APK that got v3.10 JS through a live update | No plugin in the binary → stays on `NullNotifier`; the page says "Perlu update aplikasi". Nothing is faked. |

## Permission

Android 13+ needs `POST_NOTIFICATIONS`. The app asks **only** after the user switches *Aktifkan notifikasi* on and taps
*Simpan pilihan*. It never asks on launch (e2e-tested). If the user denies, the page explains where to enable it in Android settings.

## Scheduling

- `public/js/notify.js`: adapter contract, `NullNotifier`, `nativeAdapter(LocalNotifications)`, `installNative()`.
- `public/js/views-notify.js`: settings UI and the scheduler `NOTIF`.
- Reminders for the **next 14 days** (max 60) are built by `HMTP.buildReminders` from the real plan, logs and the active race event,
  then the previous set is cancelled and the new set scheduled. This happens on start, when the app returns to the foreground,
  after any data change (persist), and after renders (which catches plan changes synced from another device). The work is skipped
  when the reminder list, date and timezone are unchanged.
- **Inexact by design:** each notification has `isExactNotification:false` and `allowWhileIdle:true`, which makes the plugin use
  `AlarmManager.setAndAllowWhileIdle` (Doze-safe, may be batched by a few minutes). The plugin's `SCHEDULE_EXACT_ALARM`
  permission is removed from the merged manifest (`tools:node="remove"`).
- **Timezone change:** the timezone is part of the schedule signature, and the last-scheduled zone is stored in `hmtp:notif:tz`.
  Opening or resuming the app in a new zone re-plans every reminder in local wall-clock time.
- **Limit:** if the app is not opened for 14 days, the horizon runs out. The status card says to open the app at least once every 2 weeks.

## Channels and categories

| Channel id | Name | Importance | Content |
|---|---|---|---|
| `workout` | Pengingat workout | high | `leadMin` before a session + the evening before |
| `race` | Hitung mundur race | high | 28/14/7/3/1 days before the active event |
| `hydration` | Pengingat minum | default | 90 min before long runs and the race (off by default) |
| `tips` | Tips latihan | low | Monday of each week, by week type |
| `weekly` | Rekap mingguan | low | Monday after a finished week, from logged runs only |
| `monthly` | Review bulanan | low | after each 4-week block |

Small icon: `ic_stat_werunit` (white silhouette generated by `scripts/make-brand-assets.mjs`); accent `#9673FF`.
Quiet hours move a reminder to the end of the quiet period, or drop it if that would be after the session starts.

## Tests

- `test/unit/notify.test.js`: adapter against a fake plugin (permission only on request, channels, inexact + allowWhileIdle,
  replaces the previous schedule, leaves other apps' notifications alone, caps at 60), plus race/hydration rules.
- `test/e2e/v4-notify.test.js`: Capacitor's real Android bridge (`native-bridge.js`) with a fake native plugin: no prompt on launch,
  one prompt after enabling, real plan reminders scheduled, no reschedule when nothing changed, disabling cancels, old APK told to update,
  web never prompts.

**Not verified here:** actual delivery on a physical phone (Doze, OEM battery savers). That needs a device test with the next APK.
